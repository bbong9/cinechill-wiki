入门

快速开始

先完成“容器能启动、管理员能登录、Emby/115 能测试、少量样本能跑通”这条最小闭环，再开启自动化。下面的命令只使用源码中实际存在的镜像、端口、挂载点和环境变量。

适用场景与前置条件

  • 适合第一次部署 CineChill，或迁移到新的 Docker/NAS 主机。
  • 主机需要能运行 Docker；长期运行推荐 Docker Compose。
  • 提前准备一个持久化数据目录、一个可被容器访问的媒体目录，以及可从 CineChill 容器访问的 Emby 地址。
  • 如果要使用 Docker 管理、网关端口自动同步或 Compose 写回，再准备 Docker Socket 和可写的 Compose 文件挂载。

最短上手顺序

  1. 部署 CineChill，管理端默认监听容器内 5256；网关默认端口为 8011。
  2. 浏览器打开管理端：首次部署默认使用账号 admin、密码 password 登录；成功后立即进入“系统配置 → 账户管理”改密。
  3. 进入“系统配置 → 服务器配置”，先测试 Emby，再填写并测试 115 Cookie。
  4. 保存 115 配置；这一步会按源码规则创建或校验标准目录，并绑定媒体整理、STRM 和相关任务。
  5. 按需配置“工具箱 → TMDB 配置”和“工具箱 → 代理配置”。
  6. 用少量自有合法授权媒体做一次整理或元数据测试，最后从顶部工具栏打开“健康检查”和“查看系统日志”。

首次登录凭据

全新部署且持久化配置中还没有 auth.json 时，初始登录信息为：

  • 账号：admin
  • 密码：password

安全要求：这组信息只用于首次进入管理端。登录后马上打开“系统配置 → 账户管理”，填写旧密码并设置新的用户名和密码；不要把默认密码用于长期运行或公网访问。

Docker run：先启动管理端

左侧变量是宿主机值；右侧 /app/... 和 /media 是容器内路径。首次使用保留默认端口，后续如果在“服务器配置”修改网关端口，必须同步修改 Docker 端口映射并重启容器。下面的单容器示例也使用当前服务名 cinechill 和最新环境变量。

# 改成你的宿主机目录；不要把真实凭据写进脚本或公开仓库
CINECHILL_DIR="/path/to/cinechill"
MEDIA_DIR="/path/to/media"
WEB_HOST_PORT="5256"
GATEWAY_HOST_PORT="8011"
STRM_HOST="your-nas-host-or-ip"

mkdir -p "$CINECHILL_DIR"/{config,fonts,templates,backups}

docker run -d \
  --name cinechill \
  --restart always \
  -p "${WEB_HOST_PORT}:5256" \
  -p "${GATEWAY_HOST_PORT}:8011" \
  -v "$CINECHILL_DIR/config:/app/config" \
  -v "$CINECHILL_DIR/fonts:/app/fonts" \
  -v "$CINECHILL_DIR/templates:/app/templates" \
  -v "$CINECHILL_DIR/backups:/app/backups" \
  -v "$MEDIA_DIR:/media" \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v /vol2/1000/docker:/vol2/1000/docker:rw \
  -e TZ=Asia/Shanghai \
  -e CHILLPOSTER_LOCAL_MEDIA_ROOT=/media \
  -e CHILLPOSTER_STRM_HOST="$STRM_HOST" \
  -e CHILLPOSTER_MEDIA_METADATA_WORKERS=15 \
  -e CHILLPOSTER_MEDIA_ORGANIZE_CONCURRENCY=4 \
  chillne/cinechill:latest
  • /app/config：登录凭据、服务器配置、任务和外部服务配置，必须持久化。
  • /app/fonts、/app/templates：封面字体和模板资源，按需持久化。
  • /app/backups：封面及迁移备份，建议持久化。
  • /media：标准目录会在这里创建；CHILLPOSTER_LOCAL_MEDIA_ROOT=/media 必须与挂载路径一致。
  • /var/run/docker.sock：只为 Docker 管理和部分端口/Compose 检查提供能力，是高权限挂载；不用这些功能时可以不挂载。
  • /vol2/1000/docker：用于让 CineChill 读取或修改其他容器的 Compose 文件；只有确实使用此功能时才挂载，并确认目录权限。

Docker Compose：长期运行推荐

下面按你提供的最新文件整理为 CineChill + Emby 一体化 Compose。服务名和容器名已经统一为 cinechill；Emby 的 Compose 服务名是 emby，容器名是 embyserver。

必须修改：/path/to/your/media、YOUR_NAS_IP 和 YOUR_PROXY_IP:PORT 都是占位符。CineChill 与 Emby 的媒体挂载左侧宿主机路径必须完全相同，右侧容器路径都必须是 /media。示例中的 /vol2/1000/docker:/vol2/1000/docker:rw 会授予容器修改其他 Compose 文件的能力，只在确实需要时保留。

# CineChill + Emby 服务集合
services:
  # CineChill 主服务：管理端、媒体整理、STRM 和相关任务
  cinechill:
    # CineChill 最新正式镜像；升级前建议先备份并验证版本
    image: chillne/cinechill:latest
    # CineChill 容器名称；docker logs 等命令按此名称排障
    container_name: cinechill
    # NAS 或 Docker 重启后自动拉起 CineChill
    restart: always
    # 端口映射
    ports:
      # 管理端：宿主机 5256 映射到容器内固定端口 5256
      - "5256:5256"
      # 302 / STRM 相关网关：宿主机 8011 映射到容器内固定端口 8011
      - "8011:8011"
    # 数据和媒体目录挂载
    volumes:
      # CineChill 核心配置、登录凭据、任务状态和外部服务配置
      - ./config:/app/config
      # 封面字体资源
      - ./fonts:/app/fonts
      # 封面模板资源
      - ./templates:/app/templates
      # 封面、配置和迁移备份
      - ./backups:/app/backups
      # 本地媒体库：左侧必须改成你的实际路径，并且必须与 Emby 的媒体映射完全一致
      - /path/to/your/media:/media
      # Docker 管理页读取本机 Docker 状态所需的 Socket；不用 Docker 管理功能时可移除
      - /var/run/docker.sock:/var/run/docker.sock
      # 允许 CineChill 读取或修改其他容器 Compose 文件；仅在需要时挂载，属于高权限映射
      - /vol2/1000/docker:/vol2/1000/docker:rw
    # CineChill 环境变量
    environment:
      # 时区
      - TZ=Asia/Shanghai
      # 容器内媒体根目录；必须与上方媒体挂载的右侧路径一致
      - CHILLPOSTER_LOCAL_MEDIA_ROOT=/media
      # STRM 访问主机地址；改成 NAS 或服务器在局域网中的地址，不要填 127.0.0.1
      - CHILLPOSTER_STRM_HOST=YOUR_NAS_IP
      # 媒体元数据处理并发数；性能较弱的机器可适当降低
      - CHILLPOSTER_MEDIA_METADATA_WORKERS=15
      # 媒体整理并发数；机械硬盘或低性能 NAS 可适当降低
      - CHILLPOSTER_MEDIA_ORGANIZE_CONCURRENCY=4

  # Emby 媒体服务器：与 CineChill 共用同一宿主机媒体目录
  emby:
    # Emby Beta 镜像；如果你已验证其他标签，可按实际环境替换
    image: emby/embyserver:beta
    # Emby 容器名称
    container_name: embyserver
    # 使用宿主机网络；Emby 直接监听宿主机网络栈
    network_mode: host
    # 端口说明；Host 网络模式下实际监听以宿主机状态为准
    ports:
      # Host 网络模式下实际监听以宿主机状态为准；保留端口说明方便核对
      - "8096:8096"
      # Emby HTTPS 默认端口
      - "8920:8920"
    # Emby 环境变量
    environment:
      # 容器内运行用户 ID；按提供的配置使用 root
      - UID=0
      # 容器内运行组 ID
      - GID=0
      # 附加组 ID 列表
      - GIDLIST=0
      # 时区
      - TZ=Asia/Shanghai
      # HTTP 代理；改成你自己的代理地址和端口，不要把真实地址提交到公开仓库
      - HTTP_PROXY=http://YOUR_PROXY_IP:PORT
      # HTTPS 代理；改成你自己的代理地址和端口
      - HTTPS_PROXY=http://YOUR_PROXY_IP:PORT
      # 不经过代理的本机、局域网、Emby/CineChill 访问地址；按你的网络补充实际地址
      - NO_PROXY=localhost,127.0.0.1,YOUR_NAS_IP,192.168.0.0/16,cinechill
    # Emby 配置和媒体目录挂载
    volumes:
      # Emby 配置、数据库和元数据；必须持久化
      - ./emby/config:/config
      # 媒体库目录：左侧必须与 CineChill 完全相同，右侧必须同为 /media
      - /path/to/your/media:/media
# 在保存 Compose 文件的目录执行
docker compose config
docker compose up -d
docker compose ps

# 分别查看 CineChill 和 Emby 日志
docker compose logs -f cinechill
docker compose logs -f emby

从 Docker 部署到媒体入库：按顺序完成

下面是 CineChill 与 MoviePilot、Emby、115 配合时的一条完整链路。第一次不要一次打开所有自动化：先用一部电影或一季电视剧跑通，再扩大到全库。

1. Docker 部署：先让服务稳定启动

  1. 准备持久化目录、媒体目录和 Docker Compose 文件；CineChill 与 Emby 的媒体挂载左侧宿主机路径必须一致。
  2. 启动后访问 5256 管理端，首次使用 admin / password 登录，马上到“系统配置 → 账户管理”修改凭据。
  3. 执行 docker compose ps 和 docker compose logs --tail 200 cinechill，确认容器没有反复重启。

小白注意：不要先改业务配置。容器、端口、挂载目录和权限没稳定时，后面的 Emby、115、MoviePilot 测试都会被误判为业务故障。详见 部署与首次配置。

2. 服务器配置：先接通 Emby 和 115

进入“系统配置 → 服务器配置”，先测试并保存 Emby，再测试并保存 115。保存 115 后，CineChill 会创建或校验远程标准目录以及本地“媒体库 / 真实库”目录。

通过标准：Emby 卡片显示已连接并能读到媒体库；115 卡片显示 Cookie 有效；系统健康中的路径、网关和依赖检查正常。详见 服务器配置。

3. 一条龙整理：把待处理内容整理并同步

进入“媒体整理 → 一条龙菜单”。它负责识别、重命名、分类、写入目标媒体目录，并按开关执行 STRM、元数据和 Emby 刷新。整理不是“下载”，输入必须已经出现在 CineChill 能看到的待整理目录或 115 标准目录中。

整理与同步要分清：“整理”改变文件归属、名称和目录；“STRM / 元数据同步”负责生成或更新播放入口、图片和 Emby 识别信息。第一次先关闭高风险的全量同步，确认整理记录正确后再执行同步。

4. 配置封面系统：先模板，后自动任务

封面系统建议按“资源配置 → 封面设计 → 手动预览 / 应用 → 封面备份 → 自动封面”的顺序配置。先用一个媒体库生成预览，确认效果后再创建 Cron 自动任务。

小白注意：“应用封面”可能覆盖已有封面；批量前先到“封面备份”创建快照。详见 资源配置、封面设计、封面备份、自动封面。

5. 配置 AI 助手：只做小范围辅助

AI 助手用于识别、校验、提醒或辅助运维，不是自动删除和全库重命名工具。先填写必要配置并测试，再用一条已知媒体验证结果，确认可靠后才考虑接入整理流程。

建议：让 AI 先输出建议，人工确认后再执行写入、重命名、整理或通知。详见 AI 助手。

6. 真实库与订阅：决定“要补什么”

“真实库”适合周期性读取 RSS 并找出缺失条目；“订阅系统”负责查看、暂停、恢复和删除已经创建的 MoviePilot 订阅。两者都不是下载器本身。

推荐顺序：先预览 RSS 或在“发现推荐”确认一条媒体，再发送一次 MP 订阅，回到订阅系统确认记录，最后才开启周期任务。详见 真实库、订阅系统。

7. MoviePilot 站点监控：触发下载

先在“工具箱 → MoviePilot”保存地址、API Key 和账号密码并测试连接，再进入首页“站点管理”。站点管理负责监控和筛选，不是 MoviePilot 连接配置页。

  1. 检查站点状态、质量条件、媒体类型和季集匹配。
  2. 打开候选资源，核对标题、年份、季集、分辨率和来源。
  3. 只对一条候选触发一次种子 / 下载任务，确认 MoviePilot 任务已经创建。

小白注意：站点监控成功只代表候选被发现或任务被提交，不代表已经下载、硬链接、上传或入库。后续要分别看 MoviePilot、115 秒传、整理记录和系统日志。

8. MP 硬链接 → CineChill 监控 → 115 整理目录

下载器完成后，MoviePilot 按自己的任务设置把文件硬链接到专用的“待 CineChill 处理”目录。硬链接目录必须与下载源位于同一文件系统，并且 CineChill 容器能看到同一宿主机路径。

  1. 在 MoviePilot 中确认下载目录和硬链接输出目录都是真实可写路径。
  2. 在 CineChill“115秒传”新建任务：本地监听目录选择 MP 硬链接目录，115 目标目录选择服务器配置创建的整理 / 秒传目录。
  3. 第一次使用“手动扫描”，确认校验 → 秒传 → 上传状态正常，再切换实时监听。

关键路径原则：MP、CineChill、Emby 三套容器的宿主机路径要能对应起来；容器内看到的路径不一致时，CineChill 会找不到硬链接文件，表现为“下载成功但没有整理任务”。详见 115秒传。

9. CineChill 整理入库、同步和验收

确认文件已经进入 115 整理目录或 CineChill 可见的待整理目录后，再回到“一条龙菜单”执行整理。打开 STRM / 元数据同步时，先选择增量或小范围任务。

  1. 执行一次小范围整理，确认目标媒体库路径、文件名、季集结构和 STRM 指向。
  2. 进入“整理记录”，核对成功、失败、重复、洗版、STRM 和跳过分类。
  3. 进入“系统运行日志”，用同一时间段核对下载、上传、整理和 Emby 刷新是否报错。
  4. 等待或手动触发 Emby 刷新，最后实际播放一条媒体验证路径和权限。

出现问题时按阶段排查：没有候选看站点监控；没有下载看 MoviePilot；没有硬链接看 MP 路径和任务；没有上传看 115 秒传；没有入库看一条龙与整理记录；播放失败看 STRM、Emby 刷新和系统健康。

首次验证

  1. 访问 http://你的主机地址:5256；反向代理场景则访问你配置的 HTTPS 地址。
  2. 首次部署使用账号 admin、密码 password 登录；进入“系统配置 → 账户管理”后立即修改凭据。
  3. 打开“服务器配置”，Emby 测试应能返回媒体库数量；115 测试应显示 Cookie 有效。
  4. 保存 115 配置后，从顶部工具栏打开“健康检查”，确认标准目录、媒体路径和网关状态。
  5. 运行一次小范围任务，去“整理记录”和“系统运行日志”确认结果。
  6. 用 /api/version 核对实际运行版本；Wiki 已同步的最近发布记录为 v1.0.0.69（2026-08-04）；实际运行版本仍以你的 CineChill 页面或 /api/version 返回值为准，不要只根据镜像标签猜版本。

失败排查

按下面的顺序排查，不要看到“失败”就重复点击全量任务。每一步都写明“看哪里、改什么、改完如何验证”。

1. Docker 容器启动失败或页面打不开

  1. 先执行 docker compose ps；如果 CineChill 状态不是 Up，执行 docker compose logs --tail 200 cinechill。
  2. 日志出现 port is already allocated：执行 lsof -nP -iTCP:5256 -sTCP:LISTEN 或检查 Compose 的左侧端口，改成未占用端口后重新 docker compose up -d。
  3. 日志出现挂载或权限错误：检查 ./config、./templates、./backups 和媒体目录是否存在、可读写；不要只修改容器名。
  4. 容器反复重启：保留最近 200 行日志，先解决第一条启动错误，再检查后面的连锁报错。
  5. 页面返回 502：先绕过反向代理直接访问 http://主机地址:5256；直连正常才去查代理上游地址和端口。

通过标准：docker compose ps 显示 CineChill 为运行状态，直连管理端能打开登录页，且日志不再连续重复启动。

2. 登录失败或登录后接口报 401/500

  1. 全新配置先用 admin / password；如果已经改过密码，不要反复使用默认密码，去“账户管理”确认当前凭据。
  2. 登录页能开但点击按钮报 401：确认浏览器访问的是同一个管理端地址，不要把反向代理前端和另一个旧容器混用。
  3. 报 500：打开“系统运行日志”，按时间过滤错误；同时执行 docker compose logs --tail 200 cinechill，记录接口路径和第一条异常。
  4. 修复后退出并重新登录，再只点击原来失败的一个按钮验证，不要立即运行整理任务。

3. Emby 或 115 测试失败

  1. 先看“服务器配置”的测试结果：Emby 失败只排 Emby，115 Cookie 失败只排 115，不要同时改两张卡片。
  2. 地址不要填容器内的 localhost 或 127.0.0.1；容器访问宿主机要使用可达的 NAS 地址或同网络服务名。
  3. Emby 返回 401/403：重新生成或核对 API Key；地址能打开不代表 Key 有权限读取媒体库。
  4. 115 显示 Cookie 无效：重新扫码或完整复制 Cookie，去掉首尾空格，先“测试连接”成功，再点击“保存配置”。
  5. 测试成功后才保存并进入下一步；修复后到“系统健康”确认对应项目变为正常。

4. 健康检查提示目录不存在或不可写

  1. 先确认配置里的容器路径，例如 /media，再执行 docker inspect cinechill 检查宿主机实际挂载。
  2. 在容器内检查：docker exec cinechill sh -c 'ls -ld /app/config /media && touch /media/.cinechill-write-test && rm /media/.cinechill-write-test'。
  3. 目录不存在：创建宿主机目录并重新检查 Compose 左侧路径；不要在容器内临时创建后就认为持久化已经正确。
  4. 目录只读或权限不足：修复宿主机目录属主、权限或挂载模式，重新创建容器后再检查。
  5. 媒体目录能读但不能写时，整理、STRM 和封面任务仍可能失败；必须让实际目标目录通过写入探针。

5. 一条龙执行后识别为 0、失败或目标路径错误

  1. 先确认文件真的在 CineChill 容器能看到的待整理目录，不要把 Emby 成品库根目录直接当源目录。
  2. 整理记录显示“未识别”：检查文件名、年份、季集；打开 TMDB 配置和系统日志确认元数据请求是否失败。
  3. 识别正确但路径错误：回“重命名模板”和“二级分类”核对电影/剧集模板、Season 格式和目标目录，不要直接移动成品文件。
  4. 第一次只用一部电影或一季剧集运行；确认“源文件 → 目标文件”正确后再扩大范围。
  5. 整理成功后到“整理记录”看目标路径，再到 Emby 刷新并实际打开媒体。

6. STRM、元数据或 Emby 刷新失败

  1. 先区分是“整理成功”还是“同步失败”；整理记录中的文件成功不代表 STRM 和 Emby 已完成。
  2. STRM 内容为空或地址错误：检查 CHILLPOSTER_STRM_HOST、8011 端口、反向代理和容器内路径映射。
  3. 元数据失败：在 TMDB 配置和代理配置页分别测试；只重跑失败样本，不要直接全量刮削。
  4. Emby 看不到新文件：先确认文件已落到 Emby 映射的同一个宿主机目录，再手动刷新对应媒体库。
  5. 最后实际播放一条 STRM 或本地媒体；只看到海报不算验收完成。

7. 封面预览正常但应用失败或效果不对

  1. 回“资源配置”确认模板和字体仍然存在，再回“封面设计”确认当前布局与预设匹配。
  2. 只对一个测试媒体库生成预览；预览空白时先检查字体、背景素材和媒体库读取状态。
  3. 应用前进入“封面备份”创建快照；应用后回 Emby 核对实际封面，而不是只看预览图。
  4. 批量效果不对：先停用自动封面任务，记录任务名称和目标库，再恢复对应快照或另存的稳定模板。

8. 真实库、订阅或站点监控没有产生下载任务

  1. 真实库解析为 0：先检查 RSS 地址、代理、DNS 和返回内容；解析数量为 0 时不要开启同步缺失。
  2. 解析有条目但 TMDB 匹配为 0：核对标题、年份、类型和 TMDB 配置，先手动确认一条媒体。
  3. 订阅已创建但没有任务：去订阅系统看季集范围和状态，再到 MoviePilot 任务页确认是否收到订阅。
  4. 站点没有候选：检查站点状态、质量过滤、严格匹配和媒体类型；只降低一个条件再重新搜索。
  5. 候选有但提交失败：去“工具箱 → MoviePilot”测试连接，再看 MoviePilot 外部任务和系统运行日志。

9. 下载完成后没有硬链接、115 没有上传或没有入库

  1. 先在 MoviePilot 确认下载任务确实完成，并在宿主机确认硬链接文件实际出现。
  2. 硬链接不存在：检查下载目录和硬链接目录是否同一文件系统、是否可写，以及 MP 容器是否使用正确路径。
  3. CineChill 看不到硬链接：检查 CineChill 的宿主机挂载和容器内路径，执行一次“115秒传”手动扫描。
  4. 115 秒传未命中：确认文件 SHA1 校验结果；允许真实上传时观察上传进度，第一次关闭成功后自动删除。
  5. 115 目标目录没有文件：检查任务选择的远程 CID 和标准目录，等待远程移动完成后刷新任务历史。
  6. 文件已上传但未入库：回“一条龙菜单”执行小范围整理，再到整理记录、系统日志和 Emby 刷新逐项确认。

排查记录建议：每次只改一个变量，记录操作时间、页面、按钮、错误原文和修复后的验证结果；这样下一次可以直接定位到同一个阶段。
