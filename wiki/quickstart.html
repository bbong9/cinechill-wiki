入门

快速开始

先完成“容器能启动、管理员能登录、Emby/115 能测试、少量样本能跑通”这条最小闭环，再开启自动化。下面的命令只使用源码中实际存在的镜像、端口、挂载点和环境变量。

适用场景与前置条件

  • 适合第一次部署 CineChill，或迁移到新的 Docker/NAS 主机。
  • 主机需要能运行 Docker；长期运行推荐 Docker Compose。
  • 提前准备一个持久化数据目录、一个可被容器访问的媒体目录，以及可从 CineChill 容器访问的 Emby 地址。
  • 如果要使用 Docker 管理、网关端口自动同步或 Compose 写回，再准备 Docker Socket 和可写的 Compose 文件挂载。

最短上手顺序

  1. 部署 CineChill，管理端默认监听容器内 5256；网关默认端口为 8011。
  2. 浏览器打开管理端，登录后立即进入“系统配置 → 账户管理”修改登录凭据。
  3. 进入“系统配置 → 服务器配置”，先测试 Emby，再填写并测试 115 Cookie。
  4. 保存 115 配置；这一步会按源码规则创建或校验标准目录，并绑定媒体整理、STRM 和相关任务。
  5. 按需配置“工具箱 → TMDB 配置”和“工具箱 → 代理配置”。
  6. 用少量自有合法授权媒体做一次整理或元数据测试，最后查看“系统健康”和顶部“系统运行日志”。

Docker run：先启动管理端

左侧变量是宿主机值；右侧 /app/... 和 /media 是容器内路径。首次使用保留默认端口，后续如果在“服务器配置”修改网关端口，必须同步修改 Docker 端口映射并重启容器。

# 改成你的宿主机目录；不要把真实凭据写进脚本或公开仓库
CINECHILL_DIR="/path/to/cinechill"
MEDIA_DIR="/path/to/media"
WEB_HOST_PORT="5256"
GATEWAY_HOST_PORT="8011"
STRM_HOST="your-nas-host-or-ip"

mkdir -p "$CINECHILL_DIR"/{config,fonts,templates,layouts,backups,media}

docker run -d \
  --name cinechill \
  --restart unless-stopped \
  -p "${WEB_HOST_PORT}:5256" \
  -p "${GATEWAY_HOST_PORT}:8011" \
  -v "$CINECHILL_DIR/config:/app/config" \
  -v "$CINECHILL_DIR/fonts:/app/fonts" \
  -v "$CINECHILL_DIR/templates:/app/templates" \
  -v "$CINECHILL_DIR/layouts:/app/layouts" \
  -v "$CINECHILL_DIR/backups:/app/backups" \
  -v "$MEDIA_DIR:/media" \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -e TZ=Asia/Shanghai \
  -e CHILLPOSTER_LOCAL_MEDIA_ROOT=/media \
  -e CHILLPOSTER_STRM_HOST="$STRM_HOST" \
  chillne/cinechill:latest
  • /app/config：登录凭据、服务器配置、任务和外部服务配置，必须持久化。
  • /app/fonts、/app/templates、/app/layouts：封面资源和布局，按需持久化。
  • /app/backups：封面及迁移备份，建议持久化。
  • /media：标准目录会在这里创建；CHILLPOSTER_LOCAL_MEDIA_ROOT=/media 必须与挂载路径一致。
  • /var/run/docker.sock：只为 Docker 管理和部分端口/Compose 检查提供能力，是高权限挂载；不用这些功能时可以不挂载。

Docker Compose：长期运行推荐

把以下内容保存为你自己的 Compose 文件，并将左侧宿主机路径替换为实际目录。Compose 服务名不是固定 API 名称；下面示例使用 cinechill，日志命令也按此服务名书写。

必须修改：./media 只是示例宿主机目录；请改成实际媒体路径，并保证 CineChill 与 Emby 看到的容器内媒体路径完全一致。若只使用 CineChill 的 STRM/整理功能，可不把 Emby 写进同一份 Compose，但 Emby 仍必须能访问同一媒体映射。

services:
  cinechill:
    image: chillne/cinechill:latest
    container_name: cinechill
    restart: unless-stopped
    ports:
      - "5256:5256"
      - "8011:8011"
    volumes:
      - ./config:/app/config
      - ./fonts:/app/fonts
      - ./templates:/app/templates
      - ./layouts:/app/layouts
      - ./backups:/app/backups
      - ./media:/media
      - /var/run/docker.sock:/var/run/docker.sock
      # 只有需要“写入 Compose”时才挂载；左右路径要保持为容器内可见的同一绝对路径
      # - /path/to/compose-project:/path/to/compose-project:rw
    environment:
      - TZ=Asia/Shanghai
      - CHILLPOSTER_LOCAL_MEDIA_ROOT=/media
      - CHILLPOSTER_STRM_HOST=your-nas-host-or-ip
docker compose up -d
docker compose ps
docker compose logs -f cinechill

首次验证

  1. 访问 http://你的主机地址:5256；反向代理场景则访问你配置的 HTTPS 地址。
  2. 登录后进入账户管理修改凭据。
  3. 打开“服务器配置”，Emby 测试应能返回媒体库数量；115 测试应显示 Cookie 有效。
  4. 保存 115 配置后，打开“系统健康”，确认标准目录、媒体路径和网关状态。
  5. 运行一次小范围任务，去“整理记录”和“系统运行日志”确认结果。
  6. 用 /api/version 核对实际运行版本；Wiki 已同步的最近发布记录为 v1.0.0.69（2026-08-04）；实际运行版本仍以你的 CineChill 页面或 /api/version 返回值为准，不要只根据镜像标签猜版本。

失败排查

  • 页面打不开：先执行 docker ps 和 docker logs --tail 200 cinechill，重点看端口占用、挂载权限和启动异常。
  • Emby/115 测试失败：确认地址是从 CineChill 容器可达的地址；不要把只在浏览器本机可达的 localhost 当成容器地址。
  • 健康检查提示路径不可写：检查宿主机目录权限，以及容器内看到的路径是否与配置一致。
  • 网关不可用：确认配置的反代端口与 Docker 映射一致，并重新创建容器。
  • 外部元数据失败：先在代理配置页测试，再看系统健康中的具体网络目标，不要直接重跑全库。

备份、升级与回滚

  1. 升级前停止或暂停高风险任务，备份挂载的 config、fonts、templates、layouts 和 backups。
  2. 生产环境不要长期依赖 latest；把 Compose 镜像改为已经验证过的版本标签后再执行 docker compose pull && docker compose up -d。
  3. 升级后重复“首次验证”。
  4. 回滚时把镜像改回上一个已验证标签，先恢复容器；只有确认配置文件被新版本改坏时，才在停容器后恢复备份目录。

安全边界

  • 本文只面向自有或合法授权媒体库的管理、元数据刮削、封面整理和 NAS 运维。
  • 不要把用户名、密码、Cookie、API Key、Token、Webhook 地址、真实 Chat ID、内网地址、真实路径或完整日志写进公开 Wiki。
  • 不要在公开文档中记录资源链接、分享口令、转存口令、磁力、破解、去 DRM 或绕过访问限制的方法。
  • 保存敏感配置后先做连接测试或小范围验证，再开启全量任务、定时任务和长期监听。
