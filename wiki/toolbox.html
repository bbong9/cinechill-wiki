控制台 / 工具箱

工具箱里的每张卡片对应一个独立功能。本页先告诉你每个工具解决什么问题、具体点哪里、字段怎么填，以及完成后到哪里确认结果；需要看完整字段和排障过程时，再打开对应的详细教程。

先记住这套操作顺序

  1. 左侧进入“工具箱”，用分类按钮或搜索框找到目标卡片。
  2. 打开弹窗后先看当前状态，再按本页对应章节填写字段。
  3. 有“测试 / 校验 / 立即运行”按钮时，先做一次小范围验证，再点击“保存”或“启用”。
  4. 完成后回到对应业务页、任务历史或系统运行日志确认结果；只看到“保存成功”不代表后续业务已经跑通。

推荐第一次使用：每个工具先只处理一个账号、一个目录、一条链接、一个事件或一个媒体，确认结果后再扩大范围。

01

扫码获取 115 CK

用 115 客户端扫码建立一次性会话，成功后复制 CK，再到“115 配置”中保存并测试。它适合首次配置 115 或旧 Cookie / CK 失效后的重新获取。

怎么操作

  1. 点击“扫码获取115CK”，选择页面提供的客户端类型。
  2. 点击“生成二维码”，用自己的 115 客户端扫码并确认。
  3. 等待状态从“等待”变为“已扫码”“已确认”“成功”；过期就重新生成。
  4. 成功后复制 CK，打开“115 配置”粘贴，执行目录读取或连接测试。

字段怎么填

  • 客户端类型：按你实际扫码的 115 客户端选择，选错会导致扫码后无法完成会话。
  • 二维码：只对应当前这次会话，刷新或过期后不要继续使用旧图。
  • CK 结果：必须等页面显示“成功”后再复制，不能把“已扫码”当成完成。

成功后确认

  • 115 配置页能读取目录或显示连接正常。
  • 再到秒传、转存或整理功能做一个小文件测试。

小白易错点

  • 二维码过期后继续等待；重新生成并扫码即可。
  • 只复制 CK 没有回 115 配置测试；复制成功不代表服务已配置。

02

115 定时清空

创建一个 Cron 任务，按固定时间清理指定的 115 目录，也支持手动立即运行。首次一定先用可重建的测试目录，不要直接选择成品媒体目录。

怎么操作

  1. 点击“115 定时清空”，选择“新建”。
  2. 填写“任务名称”和“Cron 表达式”，先保持低频，例如每天执行一次。
  3. 点击“浏览 115 目录”，进入具体目录并确认当前目录。
  4. 先关闭“启用任务”和“清空回收站”，保存后点击“运行”做一次手动测试。
  5. 检查任务历史和目录结果，无误后再编辑任务，打开启用并保存。

字段怎么填

  • 任务名称：写清楚用途和目录，例如“临时转存清理”。
  • Cron 表达式：决定执行时间，先确认服务器时区和下一次运行时间。
  • 清空目录：选择具体目录，不要用根目录代替测试。
  • 清空回收站：打开后会进一步清理回收站，确认任务稳定后再开启。
  • 启用任务：只控制后续定时调度，停用不会撤销已经执行的清理。

成功后确认

  • 手动运行显示成功，任务历史有本次记录。
  • 目标目录只清理了预期文件，未影响其他目录。

小白易错点

  • Cron 写对但任务未启用；先看任务开关和服务器时区。
  • 误选目录后继续点击“运行”；应立即停用并先核对目标目录。

03

网盘资源秒传

在两个 115 账号之间迁移文件或文件夹。来源账号负责读取，目标账号负责写入；两边的目录和 CK 要分别选择，不能混用。

怎么操作

  1. 填写“来源账号 CK”“目标账号 CK”和“并发数”，第一次用低并发。
  2. 点击“浏览来源”，进入具体目录，勾选文件或文件夹。
  3. 点击“浏览目标”，进入具体目标目录并确认。
  4. 确认来源数量、目标路径和并发数后点击“开始秒传”。
  5. 观察成功、跳过、失败和处理中的数量，完成后刷新目标目录核对。

字段怎么填

  • 来源账号 CK：用于读取来源文件，不能填目标账号 CK。
  • 目标账号 CK：用于写入目标目录，先确认有目录权限。
  • 并发数：影响速度和失败率；卡住或失败多时先降低。
  • 来源 / 目标目录：都要选到具体目录，首次用临时目录验证。

成功后确认

  • 任务统计与目标目录实际文件数量基本一致。
  • 抽查文件能正常打开，再扩大到下一批。

小白易错点

  • 来源和目标 CK 填反；分别浏览两个目录即可发现。
  • 取消任务后重复全部提交；已成功的文件不会回滚，应只重试失败项。

04

资源转存

把一条或多条链接提交到 115 转存流程，并统一写入默认转存目录。它适合手动提交候选，转存完成后再交给媒体整理。

怎么操作

  1. 点击“资源转存”，先在“转存目录”中浏览并选择具体目录，保存为默认目标。
  2. 在“手动转存”文本框粘贴一条链接；确认成功后再粘贴多行。
  3. 点击当前页面显示的“开始转存”，等待返回结果。
  4. 打开“转存历史”，按时间查看成功、失败和处理中的记录。
  5. 确认目标目录有文件后，再进入一条龙整理或其他后续流程。

字段怎么填

  • 转存目录：是默认写入位置，首次不要留空使用根目录。
  • 手动转存：每行放一条链接；标题、说明文字和空行不会自动变成有效任务。
  • 转存历史：用于核对任务结果；清理历史记录不会删除已完成文件。

成功后确认

  • 页面返回成功，转存历史新增成功记录。
  • 进入默认目标目录确认条目存在，再开始整理。

小白易错点

  • 输入框里只粘贴了标题或口令，解析结果为 0；先确认实际链接格式。
  • 转存历史显示成功就直接整理全量；先在 115 目录确认文件已经到位。

05

Forward 模块

配置 Forward 访问、资源库匹配、爱影搜索、Widget 和单个 TMDB ID 测试。它负责候选和联动配置，保存后仍要用单个条目验证下游流程。

怎么操作

  1. 打开“Forward 模块”，先选择“启用 Forward”和“启用资源库”，填写访问地址。
  2. 按实际需求选择“整剧模式”或“单集模式”。
  3. 需要爱影搜索时打开爱影配置，填写“Telegram ID”和“Chill Token”，保存爱影配置。
  4. 点击“保存 Forward”，确认卡片状态和搜索源数量。
  5. 用“资源测试”填写一个 TMDB ID，点击测试；再到发现页验证。
  6. 需要 Widget 时生成或刷新“Widget Token”，把新的 Widget 地址替换到自用前端。

字段怎么填

  • 启用 Forward / 资源库：分别控制模块和本地资源库匹配。
  • 访问地址：用于拼接 Widget 地址，填写实际可访问的服务地址。
  • 整剧 / 单集模式：影响后续选择方式，不会自动替你提交转存。
  • Telegram ID / Chill Token：只有启用爱影搜索时才需要。
  • Widget Token：刷新后旧 Widget 地址可能失效，要同步替换。

成功后确认

  • Forward 状态已启用，资源测试能返回单条结果或明确无结果。
  • Widget 能在自己的前端打开，发现页能看到对应候选。

小白易错点

  • 搜索有结果就认为转存可用；还要检查目标 115 和转存目录。
  • 刷新 Token 后继续使用旧地址；重新复制新 Widget 地址。

06

Webhook

让 Emby 的新增、删除等事件进入 CineChill，触发队列处理、封面更新、通知或同步。配置重点是处理引擎、预设、接收地址和启用时机。

怎么操作

  1. 打开“Webhook”，等待配置和模板加载。
  2. 选择“处理引擎”，再选择当前引擎对应的“预设”。
  3. 复制页面生成的接收地址，把它填入 Emby 的 Webhook 配置。
  4. 先在 Emby 发送一次测试事件，确认 CineChill 的 Webhook 队列收到事件。
  5. 确认无误后保存并启用，再产生一个可控的新增事件观察完整链路。
  6. 到“系统运行日志”查看收到事件、识别媒体、处理和写回结果。

字段怎么填

  • 处理引擎：按需要的封面 / 处理布局选择，选项由当前模板资源提供。
  • 预设：必须选择当前引擎下可用的模板；切换引擎后重新确认。
  • 接收地址：直接复制页面生成的 /api/webhook 地址，不要手动改路径。
  • 删除同步：当前页面提示由后端强制开启，保存时会保持开启，不能按普通开关理解。

成功后确认

  • Emby 测试事件在 Webhook 队列出现。
  • 系统日志能按时间看到事件进入和后续处理状态。

小白易错点

  • Emby 返回 404 / 502；先检查反向代理路径、端口和上游可达性。
  • 事件已收到但没有封面；再检查事件类型、模板和目标媒体是否匹配。

07

飞牛论坛签到

保存签到 Cookie 和调度参数，先校验并手动签到，确认历史记录正常后再开启定时签到。

怎么操作

  1. 填写“Cookie”，再按需要修改 Cron、最大重试次数、重试间隔和历史保留天数。
  2. 按需打开“发送签到通知”，先点击“校验 Cookie”。
  3. 校验成功后点击“立即签到”，查看最近结果和历史。
  4. 确认当天签到成功后，打开“启用定时签到”，点击“保存”。
  5. 以后从最近结果、下次运行时间和历史记录确认调度是否正常。

字段怎么填

  • Cookie：填写当前账号的完整 Cookie，校验失败就先更新它。
  • Cron：决定后台签到时间，先确认服务器时区。
  • 最大重试次数 / 重试间隔：控制临时失败时的重试，不要设置过高。
  • 历史保留天数：只影响本地签到记录的保存时间。
  • 发送签到通知：调用系统通知配置，不需要在本页重复填写通知渠道。

成功后确认

  • 手动签到结果显示成功或已签到，历史中新增当天记录。
  • 开启定时后页面显示待调度和下一次运行时间。

小白易错点

  • Cookie 未校验就打开 Cron；先手动校验和签到。
  • 通知失败就认为签到失败；以最近结果和历史中的签到状态为准。

08

Telegram 监听

登录 Telegram 账号，读取可用群组 / 频道，选择监听目标和转存目录，再启动监听服务。完整链路是“登录 → 选目标 → 选目录 → 保存 → 开启”。

怎么操作

  1. 填写“API ID”“API Hash”和“手机号”，点击“发送验证码”。
  2. 填写验证码；开启两步验证时，再填写两步验证密码并点击“登录”。
  3. 登录状态显示成功后点击“读取目标”，等待群组 / 频道列表加载。
  4. 把需要监听的目标加入已选列表，点击“保存目标”。
  5. 选择系统转存目录，或切换到自定义 115 目录后浏览并确认目录。
  6. 点击“保存监听配置”，最后打开账号监听开关。

字段怎么填

  • API ID / API Hash / 手机号：按页面登录流程填写，三者要属于同一个 Telegram 账号。
  • 验证码 / 两步验证密码：只在当前登录步骤填写，验证失败就按页面提示重新登录。
  • 监听目标：已选目标才会进入监听范围，列表加载后不要只凭名称猜测。
  • 转存目录：系统目录开箱即用；自定义 115 目录需要额外浏览和保存。
  • 监听开关：保存配置后再开启，服务状态以运行中 / 待机显示为准。

成功后确认

  • 账号显示已登录，监听服务显示运行中或待机。
  • 用一条可控测试消息验证“收到 → 匹配 → 转存提交”三阶段。

小白易错点

  • 登录成功但没有消息；检查已选目标、账号是否加入目标会话和转存目录。
  • 同时开启多个监听配置导致重复；先停用其他实例，只保留一个测试。

09

MoviePilot

在 CineChill 中配置 MoviePilot 地址、持久 API Key 和账号密码，并测试 CineChill 到 MoviePilot 的连接。站点监控仍要到“站点管理”单独配置。

怎么操作

  1. 填写“MoviePilot 地址”“持久 API Key”“用户名”和“密码”。
  2. 点击“保存配置”保存，或点击“测试连接”让页面保存后立即测试。
  3. 查看“可用能力”，确认连接、常规接口和流式搜索状态。
  4. 回到“发现推荐”或“订阅系统”对一个条目做一次订阅验证。
  5. 需要站点监控时，另到首页“站点管理”配置和测试，不要只看本页连接状态。

字段怎么填

  • MoviePilot 地址：填写 CineChill 容器能够访问的服务地址，不要只按浏览器地址判断。
  • 持久 API Key：用于常规 API 调用；页面已保存时可按提示留空保留原值。
  • 用户名 / 密码：用于原生流式搜索，不能用 API Key 代替。
  • 测试连接：只验证 CineChill 与 MoviePilot 的连接和认证，不代表站点、下载器都正常。

成功后确认

  • 配置状态变为已配置，连接测试和可用能力显示正常。
  • 发现页发出一条订阅后，订阅管理和 MoviePilot 外部任务能看到记录。

小白易错点

  • 浏览器能打开 MoviePilot 但 CineChill 测试失败；检查容器网络和服务地址。
  • 把站点监控当成连接配置的一部分；站点管理要单独完成筛选和测试。

10

代理配置

配置 CineChill 后端访问 TMDB、图片源、Docker Registry 等外部服务时使用的全局代理。保存后要回真实业务页面测试，不能只看代理弹窗。

怎么操作

  1. 点击“代理配置”，在“网络代理地址”中填写代理地址。
  2. 支持 http、https、socks4、socks5、socks5h 协议。
  3. 先点击“测试连接”，确认返回连接状态、HTTP 状态和耗时。
  4. 测试成功后点击“保存”。
  5. 回 TMDB、发现推荐、Docker 管理或系统健康执行实际目标测试。

字段怎么填

  • 网络代理地址：按页面格式填写，例如 http://host:port 或 socks5://host:port。
  • 协议：必须和代理服务实际协议一致，不能把网页 URL 当代理地址。
  • 测试结果：说明探测目标能否访问，不等于每个外部域名都能访问。
  • 内网服务：如果代理导致 Emby / MoviePilot 变慢，再检查绕过规则和容器网络。

成功后确认

  • 弹窗测试连接成功并显示合理耗时。
  • 实际失败的 TMDB API、图片或 Docker 目标在系统健康中恢复正常。

小白易错点

  • 只在浏览器里能用代理；CineChill 是后端发起请求，要从容器网络判断。
  • 代理测试成功但某个服务仍失败；按具体目标域名继续检测，不要重复保存同一地址。

11

TMDB 配置

填写 TMDB API Key，按需填写豆瓣 Cookie，为发现推荐、缺集统计、封面识别和媒体整理提供元数据。这个弹窗没有独立测试按钮，必须回业务页面验证。

怎么操作

  1. 点击“TMDB 配置”，填写“TMDB API Key”。
  2. 需要中文补充信息或相关发现源时，再填写“豆瓣 Cookie”；不需要可以留空。
  3. 点击“保存配置”，刷新弹窗确认配置状态仍然存在。
  4. 打开“发现推荐”或“缺集统计”，用一个已知片名 / 剧名查询。
  5. 再对单个媒体运行识别或封面任务，确认标题、年份、季集和海报都能返回。

字段怎么填

  • TMDB API Key：用于 TMDB 元数据请求，是本页的主要字段。
  • 豆瓣 Cookie：可选辅助字段，支持多行；留空不会阻止基础 TMDB 流程。
  • 代理：在“代理配置”单独维护，本页没有代理输入框。
  • 测试按钮：当前页面没有独立 TMDB 测试按钮，不要按旧截图寻找。

成功后确认

  • 发现页能返回正确标题和海报，缺集统计能读到预期季集。
  • 小范围整理能正常匹配元数据，再考虑批量运行。

小白易错点

  • 只看到保存成功就认为 TMDB 可用；必须在发现、缺集或整理中发起真实请求。
  • 只有图片加载失败却反复更换 API Key；先单独检查图片域名和代理。

工具箱统一排查顺序

  1. 先看页面状态：确认是不是没有保存、没有启用、目标目录没选，或筛选条件把卡片隐藏了。
  2. 再看工具自己的结果：测试 / 校验 / 立即运行失败时，先按对应章节修复，不要跳到下游页面反复重试。
  3. 再看下游结果：连接测试通过后，用一个条目、一个文件或一个事件验证真实业务链路。
  4. 最后看系统日志：按时间和模块搜索，区分配置错误、网络错误、权限错误和任务处理错误。

如果容器重建后所有工具状态都消失，优先检查 /app/config 是否正确持久化、目录是否可写；如果只有某一个工具失败，就只回该工具对应的详细教程排查。
