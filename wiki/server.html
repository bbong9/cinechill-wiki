控制台 / 服务器配置

截图来自 2026-08-14 本地 CineChill 管理端；Emby 地址、API Key、115 Cookie、内网地址和账号信息已脱敏。

服务器配置

服务器配置页同时维护 Emby 和 115 主账号。Emby 保存负责媒体库连接；115 保存除了凭据外，还会触发标准目录创建和相关模块绑定。

适用场景与前置条件

  • 首次部署、Emby 地址/API Key 变化、115 Cookie 过期、网关端口变化时使用。
  • Emby 地址必须是 CineChill 运行环境可访问的地址；浏览器能访问不代表容器也能访问。
  • 准备 Emby API Key，以及 115 Cookie；如果要执行回收站清理，再准备回收站安全码。

配置 Emby

  1. 在 Emby 卡片填写“配置名称”。它只是当前配置的显示名称。
  2. 填写“Emby 地址”，例如使用容器网络时可填写页面占位符所示的服务地址形式。
  3. 按需填写“外网地址（用于图片展示 / Emby 跳转）”。它不是容器内部连接地址。
  4. 填写“Emby 密钥（API Key）”。
  5. 填写“反代端口号”，必须是 1-65535 的数字；默认值为 8011。
  6. 先点击“测试连接”，确认返回媒体库数量，再点击“保存 Emby”。测试不会替代保存。

保存 Emby 只更新 Emby 配置；如果反代端口发生变化，后端会尝试通过 Docker/Compose 同步并重启当前容器，但前提是 Docker Socket 和可写 Compose 条件满足。

配置 115

  1. 填写“名称”和完整的“115 Cookie”，或点击“扫码登录”生成二维码并在扫码成功后“写入配置”。
  2. 点击“测试连接”，确认返回 Cookie 有效；测试不会把输入自动保存。
  3. 填写“回收站安全码”（仅在需要清理回收站时使用）。
  4. 按需打开“启用同播复制”。它用于多人同时观看同一视频时生成副本，不是网盘登录开关。
  5. 点击“保存配置”。保存会持久化 115 配置，并创建/校验标准目录与本地目录。

字段与自动创建目录

  • 115 Cookie：用于 115 连接、转存、秒传、整理和目录检查。
  • 回收站安全码：手动清理或计划清理回收站时使用；不要与登录密码混淆。
  • 启用同播复制：控制同播副本策略，保存后由后端读取。
  • 标准目录：保存时以远程根目录名（默认“影视库”）创建“媒体目录、秒传目录、失败目录、转存目录、重复目录、洗版目录”；本地根目录下创建“媒体库”和“真实库”。
  • 网关端口：实际由 Emby 配置中的反代端口决定，Docker/NAS 必须发布相同端口。

首次验证

  1. Emby 卡片显示“已连接”，并读取到预期媒体库。
  2. 115 卡片显示“Cookie 有效”。
  3. 保存 115 后，打开系统健康确认“115 标准目录”“媒体库本地路径”“真实库本地路径”正常。
  4. 运行一个小范围整理/STRM 测试，确认结果路径和 Emby 刷新符合预期。

失败排查

  • Emby 测试失败：检查地址、API Key、HTTPS 证书可达性和容器网络；先不要运行整理任务。
  • 115 Cookie 无效：重新扫码或更新 Cookie 后再测试；保存新 Cookie 会使旧客户端缓存失效并刷新相关监听。
  • 保存 115 失败：通常是 Cookie 无效、本地媒体根目录不可写或远程目录创建失败；查看错误提示和系统日志。
  • 网关未监听：检查反代端口是否已经发布，若不是 Compose 管理或 Compose 未挂载，手动更新端口映射并重建容器。
  • 标准目录检查失败：先修复 Cookie，再重新保存配置，让后端重新解析远程目录 CID。

备份与回滚

  • 修改前备份持久化配置目录；其中 115/Emby 配置和登录凭据是高价值数据。
  • 如果新目录绑定不符合预期，先停止自动任务，恢复配置备份，再启动并重新运行系统健康。
  • 不要为了回滚直接删除远程 115 目录；远程目录删除可能造成不可逆的数据损失。

它在完整流程中的作用

服务器配置是所有后续功能的地基：Emby 决定 CineChill 能否读取媒体库，115 配置决定远程标准目录、秒传、整理和真实库任务能否工作。两张卡片都要“测试成功”后再保存，不能只填写地址就开始整理。

小白推荐的保存顺序

  1. 先保存 Emby：测试连接能读到媒体库，再保存配置。
  2. 再保存 115：测试 Cookie 有效，再保存配置，让后端创建或校验标准目录。
  3. 打开系统健康，确认 Emby、115 标准目录、媒体库本地路径、真实库本地路径和网关均正常。

三套服务的路径必须能对应

对象应该指向小白注意
Emby 媒体库与 CineChill 使用同一个宿主机媒体根目录容器内路径也要一致，否则 Emby 看得到而 CineChill 看不到。
MoviePilot 硬链接目录下载完成后交给 CineChill 的待处理目录必须可写、同文件系统，且 CineChill 容器能访问。
115 整理目录服务器配置保存后生成的标准目录不要把根目录当成任务目标；先进入具体整理目录再选择。
本地媒体库 / 真实库CineChill 运行环境中的本地映射目录确认宿主机权限和容器内路径一致，避免任务成功但文件落不到 Emby。

不要急着做的事：不要在还没通过 Emby / 115 测试时启动站点监控、自动订阅或全量整理；错误会同时出现在多个页面，很难判断源头。

按现象排查：服务器配置

Emby 测试连接失败

  1. 先看错误类型：超时查地址和网络，401/403 查 API Key，读取媒体库为空查 Emby 用户权限和库路径。
  2. 地址不要填 CineChill 容器内的 localhost 或 127.0.0.1；同一 Compose 网络才使用服务名，Emby 使用 Host 网络时填写 NAS/服务器可达地址。
  3. 从 CineChill 容器验证可达性：docker exec cinechill sh -c 'getent hosts emby || true'；有 curl 时再请求同一个地址，浏览器能打开不能替代容器验证。
  4. API Key 重新复制后只点击“测试连接”，返回媒体库数量正确再点击“保存 Emby”。
  5. 修复后到“系统健康”确认 Emby API 正常，再进入整理或封面页面。

115 Cookie 测试失败或保存后标准目录为空

  1. 重新扫码或重新复制完整 Cookie，去掉首尾空格和换行；先测试，不要直接保存一串未验证的 Cookie。
  2. 测试显示 Cookie 有效但保存失败：检查 /media 和 /app/config 是否可写，再查看系统日志第一条错误。
  3. 标准目录缺失：保存配置会重新解析远程根目录；不要手工填写或删除 CID，先修复 Cookie 后重新保存。
  4. 系统健康中“115 标准目录”正常后，再到 115 秒传选择具体的媒体、秒传或失败目录。

网关端口可配置但访问不到

  1. 确认配置中的反代端口、Compose 左侧发布端口和反向代理上游端口是同一个值；容器内端口仍按当前镜像固定值处理。
  2. 执行 docker compose ps 和 docker port cinechill，确认端口真的发布，不要只看页面保存成功。
  3. 直连端口正常、域名不通：检查反向代理路径、WebSocket/SSE 和防火墙；直连也不通才回 Docker 端口和容器日志。
  4. 改端口后重新创建容器，再到系统健康和实际 STRM 播放各验证一次。

不要混合排查：服务器配置只先解决 Emby、115、路径和网关；MoviePilot、RSS、封面和整理任务要等这四项通过后再查。
