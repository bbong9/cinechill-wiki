通知配置

本页配置企业微信和 Telegram 的消息渠道、逐类通知开关、测试发送和模板。先完成一个渠道，再启用需要的通知类型，避免一次性打开所有自动提醒。

适用场景与前置条件

  • 需要接收媒体入库、整理、洗版、播放、任务、签到或 115 流程结果时使用。
  • 企业微信需要自建应用参数；Telegram 通知需要 Bot Token 和 Chat ID。
  • 如果要让企业微信回调/图片访问 CineChill，准备一个企业微信服务器可访问的公网 HTTPS 地址；不要把内网地址填进去。

企业微信：配置与验证

  1. 打开“企业微信通知”开关。
  2. 填写“企业 ID”“应用 AgentId”“应用 Secret”。
  3. 按企业微信回调要求填写“Token”和“EncodingAESKey”。页面显示的回调 URL 是 公网地址/api/wechat-notify/callback。
  4. 按需填写渠道专用“代理地址”和“管理员白名单”。
  5. 填写“CineChill 公网地址”，保存后再回企业微信后台完成回调校验。
  6. 点击“保存微信”，再点“测试微信”和“发送测试消息”；两者分别验证连接和实际发送。

Telegram：配置与验证

  1. 打开“Telegram 通知”开关。
  2. 填写“Bot Token”和“Chat ID”。
  3. 点击“保存 Telegram”，再点击“测试 Telegram”和“发送测试消息”。
  4. Telegram 通知会复用全局代理配置；如果消息发送失败，同时检查代理页和系统健康中的 Telegram Bot API 目标。

Telegram 账号监听、验证码登录和群组/频道选择属于“Telegram 监听”模块，不要把账号监听字段误填到通知卡片。

通知类型

企业微信和 Telegram 各自有独立开关。当前后端提供的类型包括：

  • 播放通知、入库通知、整理通知、洗版通知、转存通知。
  • 115 秒传通知、海报任务通知、媒体整理任务通知、元数据补齐通知。
  • 签到通知、其他任务通知（包括 STRM 等任务）。

关闭某个类型只影响该渠道；不要把“渠道关闭”和“某类通知关闭”混为一谈。

模板字段

  1. 在“通知模板”中展开需要修改的类型。
  2. 分别编辑“标题模板”和“正文模板”。
  3. 打开“可用变量”查看当前模板允许使用的 {{ variable }} 变量。
  4. 需要撤销自定义内容时点击“恢复默认”，然后保存对应渠道。
  5. 先用测试消息确认凭据，再用一个小任务确认真实事件模板。

备份、回滚与失败排查

  • 备份持久化配置目录；企业微信、Telegram 和全局公网地址分别保存在对应配置中。
  • 通知测试失败：先确认开关、凭据、目标 Chat ID/白名单和网络目标，再查看系统运行日志。
  • 企业微信图片无法显示：检查公网地址是否从外部可达、HTTPS/反代是否正确，以及回调路径是否保留。
  • 消息重复或过多：检查通知类型开关和模板，不要先修改核心整理任务。
  • 回滚模板时恢复备份或点击“恢复默认”；回滚渠道凭据后再次点击对应渠道的“测试微信”或“测试 Telegram”，再用“发送测试消息”验证实际发送。

按发送结果排查：通知配置

企业微信或 Telegram 测试发送失败

  1. 先只测试一个渠道，按错误区分地址/Token 错误、网络超时和模板渲染错误。
  2. 检查请求地址、Bot Token、Chat ID 等字段是否完整；真实凭据只在私有环境填写。
  3. 外网渠道失败时到代理配置和系统健康检查实际目标，不要只测试浏览器网络。
  4. 测试成功后再打开业务通知开关，并用一个低风险任务验证。

测试成功但业务没有通知

  1. 确认对应通知类型已启用，且触发的业务确实属于该分类。
  2. 在系统日志按通知模块和任务时间过滤，区分“未触发”“生成失败”和“发送失败”。
  3. 先保留一个渠道和一个通知类型，确认成功后再逐项开启其他通知。

通知重复或内容为空

  1. 检查是否同时启用了多个渠道、重复 Webhook 或同一任务被重复提交。
  2. 模板字段为空时对照触发事件实际提供的字段；修复模板后重新测试一条事件。
