代理配置

本页对应“工具箱”里的“代理配置”弹窗，配置 CineChill 后端的全局外部请求代理，并用真实的外部探测请求验证代理是否可用。它不是浏览器代理，也不是公开的网络绕行服务。

适用场景与前置条件

  • TMDB、图片源、豆瓣、Docker Hub 等外部请求在当前服务器网络中不可用或不稳定时使用。
  • 准备一个从 CineChill 运行环境可访问的代理地址；支持 http、https、socks4、socks5、socks5h 方案。
  • 代理地址应包含协议和主机；如果代理需要认证，凭据只保存在私有配置中。

逐步操作

  1. 打开“工具箱”，点击“代理配置”卡片，进入截图所示的弹窗。
  2. 填写“网络代理地址”，格式按页面占位符使用，例如 http://host:port 或 socks5://host:port。
  3. 先点击弹窗中的“测试连接”。后端会访问固定的外部探测目标，并返回连接状态、HTTP 状态和耗时。
  4. 确认结果后点击“保存”。保存只更新代理配置，不覆盖 TMDB、通知或日志字段。
  5. 回 TMDB、Docker 管理或发现页面重新执行实际业务验证。

字段含义与边界

  • 网络代理地址：写入全局设置中的 proxy_url，后端外部请求按各服务实现读取。
  • 测试结果：只说明代理能否访问探测目标；成功不保证每个第三方域名都可用。
  • 延迟：从 CineChill 后端发起请求的耗时，不是浏览器到代理的延迟。
  • 企业微信卡片还可以填写自己的渠道代理；不要把渠道专用代理和本页全局代理混为一谈。

首次验证

  1. 页面测试结果显示“连接成功”。
  2. 回到 TMDB 配置相关页面，执行一次小范围识别。
  3. 在系统健康中分别检测 TMDB、Docker Registry 或其他实际失败目标。
  4. 如果只有某个服务失败，按目标域名和服务自身配置继续排查。

失败排查

  • 提示格式无效：补全协议、主机和端口；不要把浏览器 PAC 地址、订阅地址或普通网页 URL 当作代理地址。
  • 连接超时/拒绝：从 CineChill 容器内部确认代理主机可达、端口开放、认证有效。
  • 代理测试成功但 TMDB 失败：检查目标是否被代理策略拦截，并检测具体 TMDB API/图片目标。
  • 保存后仍像直连：确认保存成功并刷新页面；后端保存会立即刷新全局运行时配置。

备份与回滚

  • 修改前备份持久化全局配置；代理 URL 可能包含用户名或密码，备份必须保持私有。
  • 回滚时恢复上一份代理配置并重新测试；如果代理故障，清空代理字段可回到直连模式。
  • 不要在公开 Wiki、Issue、截图或日志中泄露带认证信息的代理 URL。

按目标结果排查：代理配置

代理保存成功但外部请求仍失败

  1. 保存后回 TMDB、RSS 或网络检测执行真实目标测试；代理弹窗成功不代表每个目标都允许访问。
  2. 检查代理地址、端口、协议和容器可达性；不要把浏览器代理设置当成后端代理。
  3. 如果内网 Emby/MoviePilot 变慢或失败，检查 NO_PROXY/绕过规则和地址格式。

只有某一个目标失败

  1. 先看系统健康中的目标主机、HTTP 状态和延迟，区分目标服务故障与全局代理故障。
  2. 只修改一个目标的绕过或代理规则，再重新检测；不要直接关闭全局代理。
