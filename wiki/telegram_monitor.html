工具箱 / Telegram 监听

Telegram 监听通过 Telethon 账号登录读取会话，选择群组 / 频道作为监听目标，并把符合当前配置的消息送入转存流程。它不是公开频道目录，账号会话、API 信息和转存目录都属于私有运行数据。

适用场景与准备工作

  • 把自有消息通道接入 CineChill，监听已获授权的群组 / 频道消息。
  • 准备 Telegram API ID、API Hash、手机号和可接收验证码的账号；首次登录可能还需要两步验证密码。
  • 准备系统转存目录或一个可浏览的自定义 115 目录；不要把真实会话和目录写进公开文档。

按 UI 顺序操作

  1. 从“工具箱”点击“Telegram 监听”卡片，打开当前弹窗，在“账号登录”填写 API ID、API Hash 和手机号。
  2. 点击“发送验证码”，填写验证码；账号启用两步验证时再填写两步验证密码，点击“登录”。
  3. 登录状态显示“已登录”后点击“读取目标”，等待群组和频道列表加载。
  4. 在“监听目标”把需要监听的会话从可选列表切换到已选目标，点击“保存目标”。
  5. 在“转存目录”选择系统转存目录，或切换为自定义 115 目录后浏览并保存；最后点击“保存监听配置”并打开账号监听开关。
  6. 通过服务状态和系统日志确认“运行中 / 待机”变化；退出账号会撤销当前登录会话，重新监听需再次登录。

字段与状态

  • API ID / API Hash / 手机号：Telethon 登录所需参数，API Hash 和手机号不要公开。
  • 发送验证码 / 登录 / 退出账号：按登录阶段顺序使用；不要在多个浏览器窗口同时操作同一会话。
  • 读取目标：读取当前账号可见会话；“已选目标”是实际监听集合。
  • 目录模式：系统转存目录或自定义 115 目录；自定义目录需要额外浏览并确认。
  • 监听服务：显示待机或运行中，不代表每条消息都已成功转存；最终以任务历史和日志为准。

首次小范围验证

  1. 只选择一个自有、低流量的监听目标，保存后确认服务状态。
  2. 使用一条可控的测试消息，检查是否产生对应转存 / 任务记录。
  3. 确认目录和日志正确后，再增加目标；不需要的目标立即关闭开关。

常见问题、风险与回滚

  • 读取不到目标：先确认账号已登录、会话权限和网络；退出重登前先保存必要配置。
  • 监听运行但没有任务：检查已选目标、目录模式和消息是否满足后端提取规则，再看日志。
  • 误监听：关闭账号监听或从已选目标移除；已经产生的转存记录需到资源转存 / 115 目录单独处理。
  • 会话泄露：立即退出账号并在 Telegram 侧撤销异常会话，重新生成并保存必要凭据。

按监听阶段排查：Telegram 监听

账号登录或会话失效

  1. 确认 API ID、API Hash 和手机号属于自己的账号，按页面提示完成登录。
  2. 会话失效时重新登录并保存，再检查监听状态；不要把 session 字符串公开。
  3. 系统日志按 Telegram 模块过滤，区分认证失败、网络失败和消息读取失败。

群组/频道找不到或消息不匹配

  1. 先刷新群组列表，确认账号确实加入目标群组并有读取权限。
  2. 检查关键词、媒体类型、正则/过滤条件和转存目录；先关闭一个过滤条件测试。
  3. 用一条已知消息验证“收到→匹配→转存提交”三阶段，不要直接打开批量监听。

同一消息重复转存

  1. 暂停监听，记录消息 ID 和任务时间；检查是否运行了多个监听任务。
  2. 确认历史去重状态和任务启用状态，修复后用新消息做单次验证。
