控制台 / 一条龙菜单

一条龙菜单

新版一条龙菜单保留核心开关：保存整理策略、执行整理、补齐合集、STRM 同步和 ffprobe/刮削相关配置。

本页怎么用

一条龙菜单：实际操作指南

这页的关键不是“打开整理”，而是先选对解析模式和拦截条件，再分别执行整理、STRM 同步和元数据补齐。

按这个顺序操作

  1. 在“115事件监听”“整理完成自动同步STRM”“Emby刮削器”等基础开关中只打开需要的功能；解析模式只能选一种：纯文件名、智能ffprobe或全量ffprobe。
  2. 第一次使用建议选智能ffprobe，打开“拦截无有效年份”“拦截无中文名”“拦截无封面”“拦截 TMDb 季集不匹配”，避免错误媒体直接入库。
  3. 点击“保存本页配置”，只放入一个电影或一季剧集，点击“执行整理”；任务运行时不要同时启动另一条整理。
  4. 需要 STRM 时先保存 STRM 配置，再按目标选择“STRM 增量同步”或“STRM 全量同步”；全量只在首次建立或明确需要重建时运行。
  5. 元数据补齐要填写媒体库范围、Cron、并发数和 NFO/图片修复条件，点击“运行元数据补齐”后单独验收。

完成后看什么

  • 整理进度从运行变为完成，整理记录出现源路径、目标路径和成功/失败数量。
  • STRM 文件的访问地址包含正确网关端口，Emby 刷新后能看到并播放。
  • 元数据补齐后对应 NFO、图片或简介发生变化，日志能看到补齐结果。

小白最容易错在哪里

  • 同时勾选三种解析模式；实际只能按一种模式工作。
  • 全量 STRM 同步和整理同时运行，造成扫描压力和重复任务。
  • 以为“取消整理”会恢复已移动/重命名文件；取消只停止后续处理。

新版入口

左侧导航栏“媒体整理 → 一条龙菜单”。高级配置已拆到重命名模板、二级分类、服务器配置和工具箱里的对应配置页。

这页是干什么的

把待整理媒体按策略识别、重命名、分类、同步 STRM，并联动后续刷新流程。

什么时候打开它

  • 自有合法授权媒体文件已经进入待整理目录。
  • 需要小范围测试整理、刮削、命名和分类链路。
  • 修改模板或分类规则后，需要重新验证整理效果。

小白第一次怎么用

  1. 先确认服务器配置、TMDB 配置、重命名模板和二级分类已保存。
  2. 只选择少量测试文件，避免第一次就全量整理。
  3. 按需打开 115 事件监听、STRM 同步、ffprobe 和洗版相关开关。
  4. 点击“保存配置”，再点击“执行整理”。
  5. 执行后去“整理记录”和“系统运行日志”确认结果。

页面区域怎么看

  • 基础配置：控制 115 事件监听、解析方式（纯文件名/智能 ffprobe/全量 ffprobe）、Emby 刮削器和整理完成自动同步 STRM。
  • 整理任务：显示当前运行状态、待处理总数、成功、失败和可取消状态。
  • 补齐合集：用于按现有规则补充电影合集信息；它不是重新整理全部媒体。
  • STRM 同步：可选择全量或增量；全量会扫描更大范围，首次应在低峰期执行。
  • 元数据补齐：对已生成 STRM 的本地媒体补齐 TMDB 元数据，完成后可能触发 Emby 刷新。

验证方式

  1. 进度卡片从运行变为完成，成功/失败数量与整理记录大致一致。
  2. 随机抽查一个目标目录，确认文件名、季集结构和 STRM 指向正确。
  3. 在 Emby 执行或等待库刷新后，确认媒体可见、封面和元数据正常。
  4. 若运行元数据补齐，确认本地 sidecar/图片变化与 Emby 刷新结果一致。

常见问题和风险

  • 源目录不要指向已经整理好的成品媒体库，避免重复整理或误判洗版。
  • 第一次不要全量执行，先用少量文件验证；停止任务只能停止后续处理，已经移动、重命名或写入的文件不等于自动回滚。
  • ffprobe、刮削和同步都会增加任务耗时，低性能 NAS 需要降低并发，并避免多个全量任务同时运行。
  • 洗版、删除旧版本、STRM 全量同步和元数据覆盖都可能改变已有库，执行前先备份并阅读页面确认提示。

整理和同步分别做什么

动作作用完成后检查
执行整理识别媒体、重命名、分类，并把文件放到目标媒体库结构。目标路径、电影 / 剧集目录、季集和文件名。
STRM 同步生成或更新播放入口，使 Emby 能按规则读取远程或网盘媒体。STRM 内容、目标路径和 Emby 播放链路。
元数据同步补齐 TMDB 信息、图片或 sidecar，帮助 Emby 识别和展示。Emby 刷新后标题、封面、简介和季集。
补齐合集根据现有规则补充电影合集关系，不等于重新整理全库。只影响识别到的合集，不要把它当成下载任务。

硬链接目录如何进入整理

  1. MoviePilot 下载完成并生成硬链接后，确认硬链接目录中的文件能被 CineChill 容器读取。
  2. 如果使用 115 事件监听或 115 秒传链路，先确认文件已到服务器配置创建的整理目录。
  3. 回到本页先保存配置，再只选择少量文件执行整理。
  4. 整理完成后到“整理记录”核对源文件、目标文件和处理结果，再决定是否执行全量 STRM / 元数据同步。

关键提醒：停止任务只停止后续处理，不会自动撤销已经移动、重命名、写入 STRM 或刷新 Emby 的动作；第一次一定要用测试目录和小样本。

按结果排查：一条龙整理与同步

待处理数量为 0，或执行后没有任何记录

  1. 在宿主机确认文件存在，再在容器内执行 docker exec cinechill sh -c 'find /media -maxdepth 3 -type f | head'；容器看不到的文件不会进入任务。
  2. 确认监听的是待整理目录，不是已经入库的成品目录，也不是 MoviePilot 容器内才存在的路径。
  3. 检查文件权限和扩展名；目录可读但文件不可读时，任务可能显示扫描成功却识别为 0。
  4. 重新保存配置后只运行一份小样本，去整理记录按时间过滤确认是否真的创建了任务。

文件被识别成错误的电影、年份或季集

  1. 先在整理记录打开详情，记录原文件名、识别标题、年份、TMDB ID 和目标路径。
  2. 电影错误通常检查标题/年份；剧集错误还要检查季号、集号和文件名中的特殊字符。
  3. 确认 TMDB 配置和代理正常后再重跑同一个文件；不要先改全库规则。
  4. 验证无误后，再修改重命名模板或二级分类，并用另一份测试文件复核。

整理成功但文件落错目录或重复整理

  1. 对照整理记录中的源路径和目标路径，回“重命名模板”“二级分类”检查电影/剧集目标规则。
  2. 确认源目录没有包含成品媒体库；成品目录再次作为源目录会造成重复、洗版或跳过。
  3. 暂停自动任务，先用一个文件修正规则；不要用文件管理器批量移动来掩盖规则错误。
  4. 修复后再次执行同一个样本，确认目标路径、文件名和 Emby 映射一致。

整理成功但 STRM、元数据或 Emby 没有更新

  1. 把“整理成功”“STRM 成功”“元数据成功”“Emby 刷新成功”分别看，不要用一个成功状态代替全部结果。
  2. STRM 错误检查 CHILLPOSTER_STRM_HOST、8011 发布端口和容器内媒体路径；生成后打开 STRM 内容确认地址指向正确。
  3. 元数据错误先测试 TMDB/代理，再只重跑失败样本；全量同步应放到小样本验证之后。
  4. Emby 不显示时先确认目标文件已经落在 Emby 的同一宿主机映射，再手动刷新媒体库并实际播放。
