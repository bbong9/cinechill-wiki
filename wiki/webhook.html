工具箱 / Webhook

Webhook 页配置 Emby 事件接收地址、封面处理引擎 / 预设和删除同步。保存后，Emby 等外部系统可把事件发到 CineChill 的 /api/webhook 接收路由；地址属于私有服务入口，不应公开。

截图来自 2026-08-14 本地 CineChill 管理端；接收地址、域名、凭据和真实事件不展示。 截图会跟随 Wiki 外观开关：浅色模式显示日间截图，深色模式显示夜间截图；截图仅用于说明布局，敏感字段不作为公开文档内容。

适用场景与准备工作

  • 让自有 Emby 的媒体新增、删除等事件进入 CineChill，触发通知、真实库同步或封面刷新等已有处理。
  • 准备可从 Emby 访问的 CineChill 地址、HTTPS / 访问控制方案和已有封面模板；模板由后端的模板列表提供。
  • 不要把接收地址直接暴露到公网裸奔；至少使用认证、HTTPS、反向代理访问控制或私网入口。

按 UI 顺序操作

  1. 从“工具箱”点击“Webhook”卡片，打开当前弹窗，等待配置和模板加载。
  2. 在页面选择处理引擎，再从该引擎的预设列表选择模板；切换引擎后预设会按当前引擎重新归一化。
  3. 确认页面显示的“删除同步”说明；当前 UI 提示该开关由后端强制开启，保存时会保持开启，不能把它当作可关闭的删除保护。
  4. 先保持 Webhook 停用，复制页面生成的接收地址到自有 Emby Webhook 配置，完成一次测试事件后再点击保存 / 启用。
  5. 保存后查看页面状态，再到系统运行日志确认事件是否进入队列和处理。

字段解释

  • 启用：控制接收配置是否生效；停用不会撤销已经进入队列的事件。
  • 处理引擎：选择封面处理布局 / 引擎；选项来自当前模板资源。
  • 预设：当前引擎下的模板文件；模板删除或升级后可能需要重新选择。
  • 接收地址：页面根据当前站点 origin 拼接 /api/webhook，不要把真实值贴进公开文档。
  • 删除同步：页面提示由后端强制开启，保存时会保持开启，确保 Emby 删除事件进入后端处理链路。

首次小范围验证

  1. 只选择一个已有模板、保持停用，先复制地址到自有 Emby 并发送一次测试事件。
  2. 保存 / 启用后，再产生一个可控的媒体新增事件，检查 Webhook 队列和系统日志。
  3. 如果验证封面，先对单个媒体库或单个条目观察，不要直接批量覆盖。

常见问题、风险与回滚

  • 事件无记录：检查 Emby 到接收地址的网络、HTTPS、反向代理和访问控制；再看 CineChill 的 Webhook 队列。
  • 模板下拉为空：先到封面资源配置确认模板存在，再刷新 Webhook 页面。
  • 误触发批量处理：先停用 Webhook，暂停后续自动化，再按队列 / 日志判断已处理范围；已经写入的封面或同步结果要从封面备份 / 媒体库侧恢复。
  • 不要在公开 Wiki 发布真实 Webhook URL、内网域名、签名信息或事件原文。

按事件链路排查：Webhook

Emby 发送事件但 CineChill 没有记录

  1. 确认 Emby 配置的 Webhook 地址指向 CineChill 可达的公开/内网入口，并包含正确路径。
  2. 先用一个测试事件，随后在系统日志按 webhook 模块和时间查是否收到请求。
  3. 反向代理返回 404/502 时先修上游路径和端口，再查事件内容。

事件收到但封面/同步没有执行

  1. 检查事件类型、封面引擎、预设和目标媒体库是否匹配。
  2. 日志中区分收到事件、识别媒体、生成封面和写回 Emby 四个阶段。
  3. 先关闭删除同步和批量动作，用一个事件验证成功后再打开。

重复触发或删除同步误删

  1. 暂停 Webhook 或相关自动任务，保留事件时间和媒体 ID。
  2. 检查 Emby 是否重复发送同一事件以及 CineChill 是否有重复任务。
  3. 删除同步属于破坏性动作，未验证前保持关闭。
