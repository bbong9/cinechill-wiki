系统运行日志

新版日志入口移动到顶部工具栏，是排查 500、连接失败和任务异常的第一入口。

本页怎么用

系统运行日志：实际操作指南

日志要按“时间 → 级别 → 业务分类 → 关键词”逐步缩小范围。先记录原操作和时间，再筛选，不要一上来清空日志。

按这个顺序操作

  1. 任意后台页面点击顶部“查看系统日志”，先刷新读取最近日志并确认实时连接状态。
  2. 先选择错误/警告和近 1 小时，再按业务分类筛选 115、媒体整理、Emby、Webhook、Docker 等模块。
  3. 在搜索框输入任务名、文件名、接口、状态码或错误关键词，打开相邻几条日志判断事件前后顺序。
  4. 需要更细线索时临时打开 DEBUG，复现一次问题后关闭 DEBUG 回到 INFO。
  5. 修复后用同一条操作重试，观察是否出现成功日志；清空只删除日志，不会修复任务。

完成后看什么

  • 筛选结果能对应实际操作时间和模块，实时日志能继续追加。
  • 修复后同一关键词不再出现原错误，或出现明确成功结果。

小白最容易错在哪里

  • 只复制最后一行日志，缺少前置错误；至少保留同一时间段的上下文。
  • 打开 DEBUG 后长期不关闭，导致日志噪声过大；定位完成立即恢复 INFO。

新版入口

任意后台页面顶部工具栏点击“查看系统日志”。它是弹层，不再是左侧独立主菜单页。

这页是干什么的

集中查看后端日志，并按级别、模块、时间和关键词缩小问题范围。

什么时候打开它

  • 刚点击按钮但页面没有变化。
  • 页面提示 500、连接失败、任务失败。
  • 需要定位某个任务、文件名、接口或模块的错误。

小白第一次怎么用

  1. 打开顶部“查看系统日志”，先点击刷新读取最近日志。
  2. 先保持“全部日志”，确认最近更新时间和实时连接状态；需要安静排查时暂停自动跟随。
  3. 按日志级别、业务分类、时间范围（近 1 小时/6 小时/24 小时/7 天/全部）过滤，再搜索任务名、文件名、接口或状态码。
  4. 需要更多线索时临时打开 DEBUG；定位完成后恢复 INFO，避免日志噪声和敏感信息扩大。
  5. 只复制必要的时间、模块、错误摘要和请求结果；修复后刷新或观察实时流，确认同类错误不再出现。

页面区域怎么看

  • 级别筛选：全部、错误、警告、信息、调试；调试级别需要先开启 DEBUG 输出。
  • 业务分类：系统、媒体整理、元数据补齐、115、STRM、真实库/发现、通知、Webhook、Docker、Emby、MoviePilot 等。
  • 时间范围：近 1 小时、近 6 小时、近 24 小时、近 7 天或全部时间。
  • 搜索框：按任务名、文件名、接口、状态码或错误关键词检索。
  • 暂停/继续、刷新、清空：暂停实时追加、重新读取日志或清空当前后端日志；清空不会恢复。

验证方式

  1. 刷新后能看到最近日志，开启自动刷新时状态显示“实时连接”。
  2. 选择业务分类、时间范围和关键词后，结果数量与内容都符合筛选条件。
  3. 临时开启 DEBUG 后能看到调试信息，关闭后回到 INFO；调试筛选不再显示旧的 DEBUG 噪声。
  4. 修复后重新执行原操作，日志出现成功结果或不再出现原错误。

常见问题和风险

  • 日志可能包含内网地址、路径、用户信息、文件名或接口参数，公开前必须脱敏。
  • “清空日志”会删除后端保留的当前日志，不能当作解决问题；清空前先保存必要摘要。
  • 调试日志会增加噪声和存储量，排查完成后恢复 INFO。
  • 实时连接断开时先手动刷新，再检查浏览器/反向代理是否支持 SSE；不要把断流误判成业务任务停止。

日志怎么查才有结果

  1. 先记下操作时间、页面、按钮、文件名或任务名；没有时间范围的“最近日志”很难定位。
  2. 先筛选“错误”和“警告”，再按模块选择 115、媒体整理、Emby、MoviePilot、STRM 或 Docker。
  3. 搜索状态码、任务 ID、文件名或错误关键词；先看第一条异常，后续堆栈通常只是连锁报错。
  4. 记录错误摘要、模块和时间，不要公开复制 Cookie、API Key、内网地址、完整路径或整段日志。
  5. 修复后重新执行原操作，刷新日志确认出现成功记录或原错误不再出现。

按错误类型判断

  • 401/403：优先回对应配置页检查凭据和权限。
  • 404：检查地址、接口路径、服务版本或资源是否已被删除。
  • 连接超时：从容器网络查地址、DNS、代理和防火墙。
  • 权限/只读：检查宿主机目录属主、容器映射和目标文件系统。
  • 任务失败：打开整理记录、115 任务历史或 MoviePilot 外部任务看业务阶段。
