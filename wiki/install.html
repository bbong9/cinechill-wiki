部署与首次配置

本页把部署、持久化目录、首次配置、验证、升级和回滚串成一条可执行流程。生产环境优先 Docker；源码运行适合本地开发和问题复现。

适用场景与前置条件

  • Docker/NAS：适合长期运行，需 Docker、Docker Compose、可写持久化目录和能访问外部服务/Emby/115 的网络。
  • 源码运行：适合开发调试，需 Python 虚拟环境、依赖文件、Node.js 和 npm；前端构建后由主程序提供静态页面。
  • 提前规划管理端端口 5256、网关默认端口 8011、媒体挂载路径和备份位置。

Docker Compose 部署

推荐把 Compose 文件与 config、fonts、templates、layouts、backups 放在同一个项目目录。需要 Docker 管理时再挂载 Socket；需要“写入 Compose”时还要让容器看到可写的 Compose 文件。

services:
  cinechill:
    image: chillne/cinechill:latest
    container_name: cinechill
    restart: unless-stopped
    ports:
      - "5256:5256"
      - "8011:8011"
    volumes:
      - ./config:/app/config
      - ./fonts:/app/fonts
      - ./templates:/app/templates
      - ./layouts:/app/layouts
      - ./backups:/app/backups
      - ./media:/media
      - /var/run/docker.sock:/var/run/docker.sock
      # 按需挂载 Compose 项目根目录，且容器内路径必须与 Docker 标签记录的路径一致
      # - /path/to/compose-project:/path/to/compose-project:rw
    environment:
      - TZ=Asia/Shanghai
      - CHILLPOSTER_LOCAL_MEDIA_ROOT=/media
      - CHILLPOSTER_STRM_HOST=your-nas-host-or-ip
docker compose up -d
docker compose ps
docker compose logs -f cinechill

源码运行

源码运行不需要 Docker Socket；如果要用 Docker 管理功能，仍需运行在能访问 Docker Socket 的环境中。

source .venv/bin/activate
pip install -r requirements.txt

cd frontend
npm install
npm run build

cd ..
python main.py

主程序默认监听 5256，网关按 115/Emby 配置启动；本地访问可使用 http://127.0.0.1:5256。

首次配置顺序

  1. 访问登录页，确认页面可打开。
  2. 进入“系统配置 → 账户管理”，使用旧密码设置新用户名和新密码。
  3. 进入“系统配置 → 服务器配置”，填写 Emby 地址/API Key，点击“测试连接”后点击“保存 Emby”。
  4. 填写 115 Cookie，点击“测试连接”；确认有效后点击“保存配置”。保存会创建或校验标准目录并更新相关绑定。
  5. 进入“工具箱 → TMDB 配置”和“代理配置”，按需保存；代理页有独立连接测试，TMDB 页没有独立测试按钮。
  6. 用少量自有合法授权媒体验证整理、STRM 或封面链路，再打开自动任务。

持久化目录与默认资源恢复

  • /app/config：核心运行状态和敏感配置；迁移、升级前优先备份。
  • /app/fonts、/app/templates、/app/layouts：封面系统资源。
  • /app/backups：封面/迁移备份。
  • 容器启动时会从镜像的 defaults 复制缺失文件，但只复制不存在的文件，不覆盖已有用户文件；这不是完整备份，也不会替代主动回滚。

部署后验证

  1. 执行 docker compose ps，确认容器处于运行状态。
  2. 访问管理端，并用 curl http://127.0.0.1:5256/api/version 或页面版本信息确认服务响应。
  3. 检查“服务器配置”中的 Emby/115 测试结果。
  4. 检查“系统健康”中的配置文件、路径、Emby、网关和 Docker 项。
  5. 执行一个小任务并查看顶部“系统运行日志”。

升级与回滚

# 在 Compose 项目目录执行
# 升级前先完成目录备份
docker compose pull
docker compose up -d

docker compose ps
docker compose logs --tail 200 cinechill
  • 生产环境先锁定已验证版本；源码仓库当前可见最新发布记录为 v1.0.0.69（2026-08-04），实际运行版本仍以 /api/version 返回值为准。
  • 回滚时把镜像改回上一个已验证标签，再执行 docker compose up -d。
  • 只有在确认配置状态被破坏时，才停止容器并恢复备份；恢复后重新做全套健康检查。

失败排查

  • 启动后立即退出：查看容器日志，区分依赖/导入错误、配置 JSON 错误、端口占用和目录权限错误。
  • 登录页能开但 API 失败：检查浏览器访问的是否是同一个管理端地址，并查看系统日志中的 401/500。
  • 健康检查路径失败：健康检查会在目标目录创建并删除临时探针文件；只读挂载或权限不足会明确失败。
  • 网关端口失败：修改 115/Emby 配置后同步更新端口发布；无 Compose 或无可写 Compose 时，不能假设系统能自动写回。

安全边界

  • 本文只面向自有或合法授权媒体库的管理、元数据刮削、封面整理和 NAS 运维。
  • 不要把用户名、密码、Cookie、API Key、Token、Webhook 地址、真实 Chat ID、内网地址、真实路径或完整日志写进公开 Wiki。
  • 不要在公开文档中记录资源链接、分享口令、转存口令、磁力、破解、去 DRM 或绕过访问限制的方法。
  • 保存敏感配置后先做连接测试或小范围验证，再开启全量任务、定时任务和长期监听。
