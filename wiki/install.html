部署与首次配置

本页把部署、持久化目录、首次配置、验证、升级和回滚串成一条可执行流程。生产环境优先 Docker；源码运行适合本地开发和问题复现。

本页怎么用

部署与首次配置：实际操作指南

不要直接照抄 Compose。先建立持久化目录、替换必须修改的变量、校验 YAML，再启动并逐项验收。

按这个顺序操作

  1. 在 NAS/服务器创建项目目录，例如 /volume1/docker/cinechill，并创建 config、fonts、templates、backups、emby/config；进入该目录保存 docker-compose.yml。
  2. 修改媒体宿主机路径、NAS IP、管理端口/网关端口和代理地址；CineChill 与 Emby 必须把同一个宿主机媒体目录映射成相同的容器内路径。
  3. 执行 docker compose config 检查配置，再执行 docker compose up -d；用 docker compose ps 确认 cinechill 和 emby 都是 Up/运行中。
  4. 访问 http://NAS_IP:5256，使用 admin / password 登录，立即到账户管理修改初始凭据。
  5. 依次配置 Emby、115、TMDB、代理；每项都先测试再保存，最后用一个文件跑整理和 Emby 播放验证。

完成后看什么

  • 容器运行，管理端可登录，重启容器后 config 中的配置仍保留。
  • docker compose logs --tail 200 cinechill/emby 没有持续启动错误，系统健康关键项正常。

小白最容易错在哪里

  • 只改 CineChill 媒体映射，Emby 仍使用另一条路径。
  • Compose 能启动但功能全失败：检查 /app/config、/media、Docker Socket 和代理挂载。
  • 使用 Host 网络的 Emby 仍把 ports 当成普通映射来改端口；以宿主机实际监听端口为准。

适用场景与前置条件

  • Docker/NAS：适合长期运行，需 Docker、Docker Compose、可写持久化目录和能访问外部服务/Emby/115 的网络。
  • 源码运行：适合开发调试，需 Python 虚拟环境、依赖文件、Node.js 和 npm；前端构建后由主程序提供静态页面。
  • 提前规划管理端端口 5256、网关默认端口 8011、媒体挂载路径和备份位置。

Docker Compose 部署

推荐把 Compose 文件与 config、fonts、templates、backups、emby/config 放在同一个项目目录。以下示例按当前 CineChill + Emby 配置整理，所有关键配置项都保留了中文 # 注释。

部署前必须修改：/path/to/your/media、YOUR_NAS_IP 和 YOUR_PROXY_IP:PORT。CineChill 和 Emby 必须使用完全相同的媒体映射；/vol2/1000/docker:/vol2/1000/docker:rw 是高权限映射，只在 CineChill 需要修改其他 Compose 文件时保留。

# CineChill + Emby 服务集合
services:
  # CineChill 主服务：管理端、媒体整理、STRM 和相关任务
  cinechill:
    # CineChill 最新正式镜像；升级前建议先备份并验证版本
    image: chillne/cinechill:latest
    # CineChill 容器名称
    container_name: cinechill
    # NAS 或 Docker 重启后自动拉起 CineChill
    restart: always
    # 端口映射
    ports:
      # 管理端：宿主机 5256 映射到容器内固定端口 5256
      - "5256:5256"
      # 302 / STRM 相关网关：宿主机 8011 映射到容器内固定端口 8011
      - "8011:8011"
    # 数据和媒体目录挂载
    volumes:
      # CineChill 核心配置、登录凭据、任务状态和外部服务配置
      - ./config:/app/config
      # 封面字体资源
      - ./fonts:/app/fonts
      # 封面模板资源
      - ./templates:/app/templates
      # 封面、配置和迁移备份
      - ./backups:/app/backups
      # 本地媒体库：左侧必须改成你的实际路径，并且必须与 Emby 的媒体映射完全一致
      - /path/to/your/media:/media
      # Docker 管理页读取本机 Docker 状态所需的 Socket；不用 Docker 管理功能时可移除
      - /var/run/docker.sock:/var/run/docker.sock
      # 允许 CineChill 读取或修改其他容器 Compose 文件；仅在需要时挂载，属于高权限映射
      - /vol2/1000/docker:/vol2/1000/docker:rw
    # CineChill 环境变量
    environment:
      # 时区
      - TZ=Asia/Shanghai
      # 容器内媒体根目录；必须与上方媒体挂载的右侧路径一致
      - CHILLPOSTER_LOCAL_MEDIA_ROOT=/media
      # STRM 访问主机地址；改成 NAS 或服务器在局域网中的地址，不要填 127.0.0.1
      - CHILLPOSTER_STRM_HOST=YOUR_NAS_IP
      # 媒体元数据处理并发数；性能较弱的机器可适当降低
      - CHILLPOSTER_MEDIA_METADATA_WORKERS=15
      # 媒体整理并发数；机械硬盘或低性能 NAS 可适当降低
      - CHILLPOSTER_MEDIA_ORGANIZE_CONCURRENCY=4

  # Emby 媒体服务器：与 CineChill 共用同一宿主机媒体目录
  emby:
    # Emby Beta 镜像；如果你已验证其他标签，可按实际环境替换
    image: emby/embyserver:beta
    # Emby 容器名称
    container_name: embyserver
    # 使用宿主机网络；Emby 直接监听宿主机网络栈
    network_mode: host
    # 端口说明；Host 网络模式下实际监听以宿主机状态为准
    ports:
      # Host 网络模式下实际监听以宿主机状态为准；保留端口说明方便核对
      - "8096:8096"
      # Emby HTTPS 默认端口
      - "8920:8920"
    # Emby 环境变量
    environment:
      # 容器内运行用户 ID；按提供的配置使用 root
      - UID=0
      # 容器内运行组 ID
      - GID=0
      # 附加组 ID 列表
      - GIDLIST=0
      # 时区
      - TZ=Asia/Shanghai
      # HTTP 代理；改成你自己的代理地址和端口，不要把真实地址提交到公开仓库
      - HTTP_PROXY=http://YOUR_PROXY_IP:PORT
      # HTTPS 代理；改成你自己的代理地址和端口
      - HTTPS_PROXY=http://YOUR_PROXY_IP:PORT
      # 不经过代理的本机、局域网、Emby/CineChill 访问地址；按你的网络补充实际地址
      - NO_PROXY=localhost,127.0.0.1,YOUR_NAS_IP,192.168.0.0/16,cinechill
    # Emby 配置和媒体目录挂载
    volumes:
      # Emby 配置、数据库和元数据；必须持久化
      - ./emby/config:/config
      # 媒体库目录：左侧必须与 CineChill 完全相同，右侧必须同为 /media
      - /path/to/your/media:/media
# 在保存 Compose 文件的目录执行
docker compose config
docker compose up -d
docker compose ps

# 分别查看 CineChill 和 Emby 日志
docker compose logs -f cinechill
docker compose logs -f emby

源码运行

Docker 是推荐的长期部署方式。源码运行命令取决于 CineChill 源码仓库对应版本；本 Wiki 不包含应用源码，以下命令只能作为源码仓库 README 的检查清单，实际执行前请以对应版本的 README、依赖文件和目录结构为准。

source .venv/bin/activate
pip install -r requirements.txt

cd frontend
npm install
npm run build

cd ..
python main.py

主程序默认监听 5256，网关按 115/Emby 配置启动；本地访问可使用 http://127.0.0.1:5256。

首次配置顺序

  1. 访问登录页，确认页面可打开；全新部署默认账号为 admin，默认密码为 password。
  2. 登录后立即进入“系统配置 → 账户管理”，在“修改登录凭据”中把默认账号密码改成自己的值。
  3. 进入“系统配置 → 服务器配置”，填写 Emby 地址/API Key，点击“测试连接”后点击“保存 Emby”。
  4. 填写 115 Cookie，点击“测试连接”；确认有效后点击“保存配置”。保存会创建或校验标准目录并更新相关绑定。
  5. 从“工具箱”分别点击“TMDB 配置”和“代理配置”卡片打开弹窗；代理弹窗有独立连接测试，TMDB 弹窗没有独立测试按钮。
  6. 用少量自有合法授权媒体验证整理、STRM 或封面链路，再打开自动任务。

持久化目录与默认资源恢复

  • /app/config：核心运行状态和敏感配置；迁移、升级前优先备份。
  • /app/fonts、/app/templates：封面字体和模板资源。
  • /app/backups：封面/迁移备份。
  • ./emby/config：Emby 配置、数据库和元数据，必须持久化。
  • 容器启动时会从镜像的 defaults 复制缺失文件，但只复制不存在的文件，不覆盖已有用户文件；这不是完整备份，也不会替代主动回滚。

部署后验证

  1. 执行 docker compose ps，确认容器处于运行状态。
  2. 访问管理端，并用 curl http://127.0.0.1:5256/api/version 或页面版本信息确认服务响应。
  3. 检查“服务器配置”中的 Emby/115 测试结果。
  4. 从顶部工具栏打开“健康检查”，检查配置文件、路径、Emby、网关和 Docker 项。
  5. 执行一个小任务并查看顶部“系统运行日志”。

升级与回滚

# 在 Compose 项目目录执行
# 升级前先完成目录备份
docker compose pull
docker compose up -d

docker compose ps
docker compose logs --tail 200 cinechill
  • 生产环境先锁定已验证版本；源码仓库当前可见发布记录仅作参考，实际运行版本仍以 /api/version 返回值为准。
  • 回滚时把镜像改回上一个已验证标签，再执行 docker compose up -d。
  • 只有在确认配置状态被破坏时，才停止容器并恢复备份；恢复后重新做全套健康检查。

失败排查

  • 启动后立即退出：查看容器日志，区分依赖/导入错误、配置 JSON 错误、端口占用和目录权限错误。
  • 登录页能开但 API 失败：检查浏览器访问的是否是同一个管理端地址，并查看系统日志中的 401/500。
  • 健康检查路径失败：健康检查会在目标目录创建并删除临时探针文件；只读挂载或权限不足会明确失败。
  • 网关端口失败：修改 115/Emby 配置后同步更新端口发布；无 Compose 或无可写 Compose 时，不能假设系统能自动写回。

部署故障要这样定位

Compose 校验失败或容器起不来

  1. 先执行 docker compose config，修 YAML 缩进、变量占位符和重复服务名；校验未通过不要执行 up -d。
  2. 再执行 docker compose ps 和 docker compose logs --tail 200 cinechill，区分端口、权限、挂载和应用启动错误。
  3. 确认 CineChill 与 Emby 的媒体左侧宿主机路径完全一致、右侧容器路径都为 /media。

页面能打开但核心功能都失败

  1. 先在服务器配置测试 Emby 和 115，再看系统健康；不要先测试封面、RSS 或 MoviePilot。
  2. 健康检查路径失败时，检查宿主机目录属主、容器内挂载和只读标记。
  3. 健康检查通过后运行一个小样本，再看系统日志和整理记录确认应用层链路。

Emby 和 CineChill 看见的不是同一套媒体

  1. 执行 docker inspect cinechill 和 docker inspect embyserver，逐项对照宿主机源路径和容器目标路径。
  2. 两边目标路径不同或一边使用匿名 Docker volume 时，先停止业务任务，修正 Compose 后重建容器。
  3. 修复后在 CineChill 和 Emby 各自列出同一个测试文件，再进行整理。
