部署与首次配置

CineChill 通常运行在 NAS 或 Docker 主机上。部署后真正决定稳定性的，是目录、端口、权限、备份和首次配置顺序。

新版首次配置顺序

  1. 部署容器或本地服务，确认管理端登录页能打开。
  2. 进入“系统配置 → 账户管理”，修改默认或临时管理员凭据。
  3. 进入“系统配置 → 服务器配置”，分别测试 Emby 和 115。
  4. 进入“工具箱”，按需配置 TMDB、MoviePilot、Webhook、代理配置等自用入口。
  5. 进入“媒体整理 → 重命名模板 / 二级分类”，确认命名和分类策略。
  6. 进入“媒体整理 → 一条龙菜单”，只用少量样本执行整理。
  7. 进入“媒体整理 → 整理记录”和顶部“查看系统日志”验证结果。
  8. 确认链路稳定后，再开启真实库、自动封面、长期监听或定时任务。

哪些目录要备份

  • config：最重要，包含账号、配置、任务状态和缓存。
  • fonts / templates / layouts：决定封面生成效果。
  • backups：封面备份套件和迁移恢复文件。
  • 升级、迁移或大规模修改前，先备份这些目录。

部署后验证

# 查看容器状态
docker compose ps

# 查看 CineChill 日志
docker compose logs -f cinechill
  • 浏览器访问管理端，确认能看到登录页。
  • 登录后打开“仪表盘”，确认媒体库总览不为 0。
  • 打开“服务器配置”，Emby 和 115 都要测试成功。
  • 打开顶部“健康检查 / 网络检测”，确认关键项正常。

升级和回滚路径

# 升级前先备份 config、fonts、templates、layouts、backups
# 然后拉取并重建
docker compose pull cinechill
docker compose up -d

# 回滚时把 compose 里的 image 改回旧 tag，再重建
docker compose up -d
  • 不要在没有备份的情况下升级生产环境。
  • 回滚时优先恢复旧镜像 tag；如果配置被新版本写坏，再恢复备份目录。
  • 回滚后重复执行“部署后验证”。

生产风险

  • 后台端口不要裸露公网；如需公网访问，应使用 HTTPS、强密码和访问控制。
  • 媒体路径必须和 Emby 看到的路径保持一致，否则整理和 STRM 会异常。
  • /var/run/docker.sock 是高权限挂载，只建议在自有 NAS / 服务器使用。
